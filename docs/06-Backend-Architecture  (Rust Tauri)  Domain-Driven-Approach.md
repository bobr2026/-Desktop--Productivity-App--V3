# Архитектура Backend (Rust Tauri) Доменно-ориентированный подход
> _«В приложениях на Tauri бэкенд — это не просто прослойка для SQL, а надежный сервер внутри десктопа. Организация кода по доменам позволяет держать логику фич изолированной и не превращать Rust-часть в свалку»._

## 🏗 Архитектурный подход

Вместо классического «слоистого» разделения (когда все команды лежат в `commands/`, а все модели в `models/`), бэкенд приложения организован по **функциональным доменам (Domain-Driven / Feature-Driven)**.

Каждая папка внутри `src-tauri/src/` представляет собой независимый модуль (домен), отвечающий за конкретную фичу приложения.

## 📂 Дерево проекта (`src-tauri/src/`)

```
src-tauri/src/
├── apps/               # Модуль управления приложениями-ярлыками
├── dock_panels/        # Настройки и логика док-панелей
├── folders/            # Работа с папками и их содержимым
│   ├── categories_folders.rs  # Категории для папок sql прямые запросы 
│   ├── entrys.rs              # Элементы,сами структуры данных
│   ├── folder.rs            # Основная сущность и IPC-команды sql прямые запросы 
│   └── mod.rs                 # Экспорт модуля
├── globol_categorys/   # Глобальные категории 
├── notes/              # Заметки, посты и блоки контента
├── tasks/              # Таски и менеджмент задач
├── workspaces/         # Рабочие пространства
├── init_db.rs          # Инициализация SQLite, миграции и схемообразование
├── lib.rs              # Точка сборки модулей и регистрация Tauri Commands
├── main.rs             # Точка входа в Rust-приложение
└── servises.rs         # Такие фичи как get_db_path, open_app, open_folder
```

## ⚙️ Анатомия доменного модуля (на примере `folders/`)

Каждый домен полностью инкапсулирует свою логику:

- **`folder.rs`** — SQL-запросы к SQLite и функции-хэндлеры с аннотацией 
- `#[tauri::command]` которые относится только к сущности  `folder` .
    
- **`categories_folders.rs` -- SQL-запросы к SQLite и функции-хэндлеры с аннотацией 
- `#[tauri::command]` которые относится только к сущности  `categories_folders` .

- `entrys.rs`** —  DTO-структуры (`#[derive(Serialize, Deserialize)]`)
    
- **`mod.rs`** — публичный API модуля. Позволяет делать чистые импорты в `lib.rs` без каши во внутренних зависимостях.
    

## 💡 Почему это решение удачное?

- **Высокая локализация изменений (Cohesion):** Если нужно доработать логику работы с `tasks` или `notes`, менять код приходится только внутри одной соответствующей папки.
    
- **Изоляция сложности:** Папка `folders` не знает про внутреннее устройство `notes` или `dock_panels`.
    
- **Лёгкий масштабируемый рефакторинг:** При переходе к единой таблице категорий (из рефакторинга БД) достаточно будет заменить дублирующиеся файлы `categories_*.rs` на единый модуль `categories/`, не ломая при этом логику `folder.rs` или `task.rs`.
    

## 🔄 Взаимодействие с React через Tauri IPC

1. **Регистрация:** В `lib.rs` все команды из модулей собираются в единый обработчик `tauri::generate_handler![...]`.
    
2. **Инициализация БД:** При запуске приложения `init_db.rs` создает/проверяет структуру таблиц в SQLite.
    
3. **Вызов с фронтенда:** React вызывает команду по имени (например, `invoke('get_folders')`), Rust отрабатывает запрос внутри `folders/folder.rs` и возвращает строго типизированный JSON.
